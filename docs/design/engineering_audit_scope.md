## 判定规则

每一处候选都沿调用方、构造入口、配置来源和运行状态追溯，给出以下一种结论：

| 结论 | 需要的证据与处理 |
| --- | --- |
| 删除 | 必填字段或依赖由构造/入口建立；路径中的相同检查没有引入新的输入或状态变化；删除后错误能到达调用者 |
| 收敛到所有者 | 同一数据在内部流转中重复解析、补值或校验；由所属包入口建立契约，内部直接使用已建立的数据结构 |
| 保留 | 处理外部输入、异步状态变化、资源生命周期或真实安全约束；说明触发条件和失败结果 |
| 待补证据 | 调用契约或运行状态尚未查清；列明缺少的证据后继续追溯 |

重点检查：

- 已完成构造的必需成员仍反复 `hasattr/getattr(..., default)`；已校验必填键仍反复 `.get()`。
- 配置缺失或读取错误后生成零值、空集合、单位变换、旧模型、旧外参或假成功。
- 捕获范围包含内部编程错误，随后仅记录警告、跳过任务或返回成功形状的数据。
- 无生产调用依据的兼容分支、仅为不完整测试替身提供的属性探测、重复参数转换。
- 一个节点拥有多个业务工作流、跨包复制算法、私有成员穿透、同一状态由多个位置写入。
- 控制器文件头的职责/接口/安全约束/结构，以及并发、生命周期代码的必要中文说明。

必要防护和正常状态表达按其语义保留：

- HTTP/CLI/YAML/JSON/ROS 请求与消息、文件、SDK、相机、TF、MoveIt 和推理结果的入口检查。
- 尚未收到首帧、没有活动任务、可选夹爪目标、合法可选参数、C0/C1/C2 轨迹等级等明确协议状态。
- 新鲜度、时间推进、代次、取消、迟到响应、请求截止时间、锁和唯一写入者约束。
- 限位/有限性、速度/加速度/jerk、碰撞、停止确认、使能准入、保护策略及标定质量门。
- 原子落盘、会话版本/请求幂等、部分发送回执、事务回滚、资源释放和工作线程错误回传。

同一目标从预览走到执行，或从接纳走到设备发送时，状态可能已经改变；分别核对各时刻的约束。
`try/except` 若承担 HTTP/ROS 错误映射、Future 结算、设备保护或清理，应收窄到相应边界并可见传播。
正常可选项使用已声明默认值；必需配置缺失与内部契约破坏尽早显式失败。
所有候选基于契约定性，匹配到某种语法仅用作定位。

## 每批消融方式

每批固定自身基线 B（包含此前已验收批次），比较以下版本：

| 版本 | 改动范围 |
| --- | --- |
| B | 当前批改动前代码及固定输入/配置 |
| N | 仅删除该批已证实冗余的判空、属性/存在性检查 |
| D | 仅清理该批错误掩盖型默认值、静默回退 |
| E | 仅删除或收窄该批冗余异常捕获，保留边界结果映射和清理 |
| S | 合并通过对照的必要精简及相关调用方/测试契约修正 |

N/D/E 各自从同一 B 派生；某类没有候选时记为不适用。
相互依赖的删除项作为一个有说明的最小改动单元，记录与单类实验的差异。
职责拆分、接口调整和节点结构变化单独给出差异，避免混入某类防御删除的效果归因。
最终版本由各批验收后的 S 依次累积形成，交付可逐批回退的差异。

对照记录：

1. 有效输入的数值/消息/文件结果、Action/Service 结果与状态顺序。
2. 外部错误的原因、返回路径、超时/取消终态及清理情况；内部契约破坏的显式失败。
3. 代码行数、分支、捕获与默认值的实际减少量，以及保留项理由；缩减量作为描述指标。
4. 有性能假说时再测耗时/调度；使用相同工作负载、运行条件与多次结果描述波动。

固定有效输入保持一致；此前静默吞错的非法输入按已确定的新错误契约检查。
测试替身应满足真实接口契约；保留真实故障替身用于检查异步、设备与存储失败。
对照差异通过独立提交/补丁组织，复用现有工具和 fixtures。

- 选择覆盖真实风险的定向检查；重大跨包、安全关键改动及最终整合按规范执行完整回归。
- 软件/仿真对照使用假驱动、既有数据或隔离后端；现场硬件验收按用户当次明确授权和安全基线进行。
