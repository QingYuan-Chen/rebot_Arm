# 真机硬件控制与执行

> 状态：IMPLEMENTED；类型：硬件执行功能说明；适用范围：`rebotarmcontroller`；软件存在不等于本轮真机授权或现场验收。

## 功能概述

`rebotarmcontroller` 是唯一访问 MotorBridge/串口和真实电机 SDK 的 ROS 包，负责反馈、夹爪、轨迹 Action 以及最后一道执行安全门。

## 当前实现

- 连接与反馈状态发布；
- 默认失能启动和显式 `/rebotarm/enable`、`/rebotarm/disable`；
- `FollowJointTrajectory`、`trajectory_stop` 和 `safe_home`；
- 六轴与夹爪状态、反馈新鲜度和错误处理；
- 夹爪位置/抓取服务及有界保持；
- 底层关节限位、格式和通信失败拒绝。

## 反馈状态来源与恢复

六轴与夹爪共用控制器已验证缓存的读取和可用性判定。采集路径依据每个电机独立的
接收序号登记样本、观测时间和错误；状态查询不访问总线、不更新时间、不写入错误。
已删除重复的 `_gripper_status_code`，夹爪控制算法仍保留位置、速度和力矩缓存。

| 反馈情况 | 对外状态码 | `ArmStatus.error_codes` 原因分类 |
| --- | --- | --- |
| 尚无可信首帧 | `255` | `WAITING_FIRST_FRAME` |
| 读取失败或请求窗口内接收序号不推进 | `255` | `READ_FAILED`，附控制器、电机或序号信息 |
| 超过反馈有效期 | `255` | `STALE`，附数据年龄和超时阈值 |
| 位置、速度或力矩含非有限数值 | `255` | `INVALID_VALUES` |
| 坐标超出对应关节/夹爪范围 | `255` | `INVALID_COORDINATE`，附名称、原始角度和边界 |
| 夹爪显式置零验证失败或未完成 | `255` | `ZERO_INVALID`，附验证详情 |
| 新鲜合法的失能、使能或电机故障反馈 | 原码 `0`、`1`、`11` 等 | 不转换为反馈采集错误；保留电机故障含义 |

原因继续通过已有 `ARM_FEEDBACK` / `GRIPPER_FEEDBACK` 错误项及日志传递，Dashboard
沿用现有错误栏。六轴仍按整臂健康状态汇总，任一轴采集错误会使六轴状态统一不可用；
夹爪按自身反馈判断。共享总线事务失败可能同时影响七个电机，不代表保护范围合并。

新反馈越限时，不得因上一条合法样本仍在缓存中而恢复健康；采集错误优先于旧样本。
合法新帧到达后清除该电机的当前采集错误，状态立即恢复为新样本的原始状态码，
结果与状态查询次数无关。夹爪有限但越限的原始坐标保留供诊断和显式置零使用，
仍报告不可用并拒绝动作。`ZERO_INVALID` 必须经下一次显式置零验证成功才清除；
已有命令失败和保护性失能记录也不会被普通新帧抹除，恢复反馈不会自动使能或续发命令。

ROS 发布使用原子快照：数值、状态码、接收序号和反馈观测时间成套读取，夹爪开口
直接由同一快照换算。六轴批次取最旧反馈时间；夹爪保留独立反馈时间，六轴读取失败时
仍发布夹爪状态。首次发布按样本年龄换算 ROS 时间，同一缓存重发沿用旧时间戳；
夹爪首帧前使用零时间戳，不可用时米制开口为 NaN。`ArmStatus` 是当前健康快照，
状态码和原因一起读取，其消息时间仍为发布时刻。新鲜合法的电机故障码可发布，
动作和使能入口的健康要求仍保留。

## 夹爪闭合端反馈容差

2026-10-26 按用户要求，闭合端反馈合法性容差由双指总开口等效 1 mm 调整为
10 mm。按当前 `-5 rad ↔ 90 mm` 映射，允许的正向角度为约 `+0.555556 rad`；
容差内的正向反馈显示为 0 mm 开口，原始电机角度保持不变。超出容差仍报告坐标
非法和状态码 `255`，使能与夹爪命令继续经过原有安全检查。

该值只用于反馈合法性判断，不扩大张开命令软限位，也不改变闭合零位、开口映射、
力矩或置零验证：显式置零仍需连续 3 帧新鲜失能反馈落在约 `±0.000763 rad` 内。
用户报告闭合后约 5 mm 指间间隙；模型几何间隙与编码器零点偏差是不同量，
本次不修改 URDF/MuJoCo 几何，不把反馈容差作为实物净开口标定。

修改随控制器进程下次启动加载；已经运行的真机进程不自动热更新。

## 夹爪张开命令范围

2026-10-26 按用户明确要求，移除目标换算和最终 MIT 下发中的 −4.9 rad 额外张开
软限位。位置请求仍限制在 0～90 mm，按现有映射得到 0～−5 rad；MIT 下发保留
−5～0 rad 标称范围，因此 90 mm 请求的目标与发送位置均可到 −5.0 rad。

反馈合法性、闭合端容差、置零验证、力矩/速度/超时和使能检查保留。
该变更消除软件目标与发送范围不一致。2026-10-26 用户确认已完成夹爪端点实机
测试，反馈无异常；端点项据此记录为用户实测通过。实际净开口标定单独记录，
真机进程不自动重启。授权与验收来源见[项目进展](../../reference/project_status.md#近期完成进展)。

## 控制器拆分的行为基线与设备边界

拆分以 `102c218` 的公共 ROS 名称、消息类型、显式使能、反馈序号/年龄、
夹爪 0～90 mm 和六轴规范限位为基线。Python SDK 固定提交为
`6a49302804f25e624995e771acb6d61896d1856d`；原目录仅保留作来源和纯计算对照。
本地 `configuration.py` 解析本包安装的 `arm.yaml/gripper.yaml`，channel 覆盖在内存完成；
只允许 damiao，验证六轴顺序、共享通道、ID 唯一性及有限参数。反馈契约是复制后的
不可变数值，MotorBridge 状态对象后续改变不会修改已验证样本。重连清除旧连接的
序号、请求和反馈缓存，并取消旧夹爪任务；必须重新收到可信首帧及显式使能。

`hardware/sdk_driver.py` 直接接 MotorBridge；`connect()` 才打开唯一 Controller，
一起注册六轴与夹爪七个句柄，关闭时逐个释放 Motor，再释放 Controller。
`runtime/controller_runtime.py` 以 Event 协作停止、有界 join 确认旧线程退出，
禁止 self-join 和第二写入者；不使用 `Thread._stop()`。低层 disable 本身不 join。
目标、速度覆盖及轨迹游标由 `execution/arm.py` 持有，位置输出由
`control/arm/position.py` 生成。没有 SDK 控制循环或额外送点线程。
生命周期和透传暂以共享总线锁串行访问；完整请求队列/仲裁归批次 6。
反馈、夹爪算法及重力保护暂留 manager，归后续批次分别提取。

`compat/legacy_backend.py` 现在仅桥接 SDK 纯 IK/路径函数，接收规范模型及数值，
返回关节数组/时间，不持有设备、目标或线程。配置临时文件桥、`RobotArm/ArmEndPos`
构造和 SDK 私有成员访问已从生产控制路径删除。旧 IK 单目标和位姿 Action 的
“送完点”完成语义暂保留；批次 6 才切换到 motion/FJT 及收敛检查。
路径中任一 CLIK 点不收敛则拒绝接纳；自动时长按规范 FK 的平移距离估算。

普通 POS_VEL/MIT 批次返回已发送、失败和未尝试电机回执；发送错误后停止剩余
普通写入、作废游标代次，去重请求共享 Controller 保护失能。模式寄存器失败报告
电机和寄存器地址，终止切换/使能且不缓存成功模式。失能尚未验证时保持
`DISABLING` 和未知输出状态，IDLE 发布或首周期竞态不能清掉故障门；再次运动
须先显式失能并验证，再重新使能。关闭失败也保留未知状态及错误，不假报已失能。
健康的目标校验/规划失败在写入前拒绝，保留当前位置保持。

`models/kinematics.py` 使用规范六轴约化模型提供纯数值 FK；ROS Pose 转换保留在门面。
`python3 scripts/check_controller_fk.py` 可复现相同输入对照：四组输入的位置差均为
0 m，姿态差最大 2.29e-16 rad，属于数值舍入；本次未发现可观测的发布数值漂移。
规范 `joint3` 命名和 J2/J3 `+0.02 rad` 限位保持不变。

文件归属及唯一批次编号见[重构规划](../../design/controller_refactor_plan.md#分批交付与完成条件)。

- 设备、模式、寄存器、反馈请求、POS_VEL/MIT/VEL 和释放归本地驱动；
  调度和线程归 runtime，目标和速度覆盖归 execution，位置输出归 control。
- 六轴和夹爪共享同一物理 channel 与 Controller，只支持当前使用的 damiao。
  默认配置保持直接入口 500 Hz、bringup 入口 100 Hz；不因迁移统一数值。
- SDK 构造打开设备、逐电机吞发送异常、寄存器失败继续和 disable 内 join
  均不能隐式保留。新驱动构造不打开；发送错误返回逐电机回执，输出不可确认时
  停止普通写入并保护失能；健康参数/任务失败停止并保持。失败不能误报已失能。
- 新生命周期和反馈仍由 manager 现有严格逻辑验证；新合法帧恢复不自动使能。
  模式/寄存器/关闭延时、回位上限 0.3 rad/s 和 20 ms 轮询归 `ProtocolTiming`；
  使能/失能沿用共享 Controller 命令后 0.05 s、最多 10 次状态轮询及 0.1 s 间隔。
- 规范模型保留 `joint3` 和 J2/J3 `+0.02 rad`，FK 发布切换前作相同关节输入对照；
  IK 与笛卡尔路径最终归 motion，批次 2～5 的纯计算桥不拥有设备或发送线程。

`python3 scripts/check_motorbridge_abi.py` 只动态加载安装库，编译临时 C++ 客户端，
核对必需符号、反馈序号能力和 State 布局；不会创建设备句柄。句柄/传输的离线
验证使用 `/dev/pts/`，已覆盖七句柄共享、反馈序号、错误与释放/重连。
真实设备切换需独立完成规划中的 2H 实机检查；软件验证没有操作真机，
历史夹爪端点验收不自动覆盖本地驱动和新周期线程。

SDK 树无独立许可文件，README 声明 MIT，尚未取得上游许可文本。本地配置、
驱动与运行时按接口和项目既有参数独立实现，不直接复制 SDK 源码；来源和后续
计算迁入许可另见[第三方说明](../../reference/third_party_notices.md)。

## 重力补偿控制

补偿使用 `rebotarm_moveit_config/config/rebotarm.urdf` 的六轴约化模型，保持
`joint1..joint6` 顺序和原始反馈坐标；夹爪关节锁定在模型零位。模型加载检查
关节限位与硬件一致，力矩上限读取 URDF effort，且不得超过前三轴 27 N.m、
后三轴 7 N.m 的软件上限。重力与雅可比使用同一模型；末端速度采用
`LOCAL_WORLD_ALIGNED`，对应 end_link 原点速度和基座坐标轴。

补偿配置位于 `src/rebotarmcontroller/config/gravity_compensation.yaml`，随包安装，
可用控制器参数或唯一硬件 launch 的 `gravity_config` 显式覆盖。保留 Kp=7、
Kd=0.8；积分按实测 dt 计算，增益 1 N.m/(rad*s)，限幅 0.5 N.m。
总力矩估计包含电机端 PD 与前馈；同时限制前馈和总力矩，以及总力矩变化率
（前三轴 108 N.m/s、后三轴 28 N.m/s）。饱和时为前馈保留协议余量，必要时降低
PD 增益。这些是软件边界，实际反馈间隔中的电机输出仍需实机验证。

`gravity_xyz_m_s2` 是 base_link 中的重力向量，默认水平安装；
`payload_mass_kg`、`payload_com_xyz_m` 是额外负载的质量与 end_link 中的质心。
默认额外负载为零，不重复加入 URDF 已有的末端 0.5 kg。URDF 缺少独立手指的
惯性，当前 MuJoCo 另外具有手指、Gemini 2 相机和支架质量；仿真与补偿交叉验证
必须显式对齐这些附加载荷。仿真网格推算出的手指质量不能当作实物称量结果。
实际安装的相机、支架、手指及抓取物负载需要测量后配置；零位和关节方向仍需
在实机逐轴核对，不能由模型加载或仿真证明。

控制频率使用 arm.yaml 的 rate（当前 100 Hz），反馈刷新上限默认 50 Hz；
不把 SDK 的 500 Hz 默认值视作实测能力。补偿中每 5 s 输出 `gravity diagnostics`，
包括实际最大周期、回调耗时、错过截止时间次数、逐轴新序号观测速率、反馈年龄
及模型路径/摘要、重力方向和负载配置，也可通过 `gravity_compensation_diagnostics()` 读取。
观测速率统计每次接收到的最新样本，不把重复缓存读取或重复 ROS 发布计为新反馈。
Python 线程与 sleep 不提供硬实时保证；新诊断用于实机采样后决定可用控制带宽。

连续三周期出现回调耗时大于配置周期或周期间隔超过 1.5 倍，停止拖动跟随，
在最新验证位置维持有界 MIT 保持，并报告 `GRAVITY_HOLD`。
模型计算异常采用同一保持路径，不让异常退出唯一写入线程。
模式切换必须全部成功，并在切换后刷新反馈；进入失败时健康硬件恢复到当前位置
POS_VEL 保持。发送失败、反馈失效、电机异常或保持恢复失败时按严重故障保护性
失能。退出补偿重新获取新反馈并确认 POS_VEL 切换结果；不在停止失败时另起写入者。

新增软件边界和模式切换连续性尚未作为当前基线实机验收结果。当前任务只完善
已有重力补偿，笛卡尔阻抗控制器仍未实现。

## 验证结果

控制器接口、失能启动、反馈刷新、使能回滚、轨迹停止和状态发布由控制器测试与分层测试覆盖。具体命令见 [系统运行命令](../../reference/commands/system_runtime.md)。

## 边界与未完成

真机启动前必须确认串口唯一占用、fresh feedback、现场净空、支撑和急停。健康但可恢复的任务失败不得把机械臂直接失能在未知姿态；软件测试不替代物理安全验收。
