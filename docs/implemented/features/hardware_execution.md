# 真机硬件控制与执行

> 状态：IMPLEMENTED；类型：硬件执行功能说明；适用范围：`rebotarmcontroller`；软件存在不等于本轮真机授权或现场验收。

## 功能概述

`rebotarmcontroller` 是唯一访问 MotorBridge/串口和真实电机 SDK 的 ROS 包，负责反馈、夹爪、轨迹 Action 以及最后一道执行安全门。

## 当前实现

- 连接与反馈状态发布；
- 默认失能启动和显式 `/rebotarm/enable`、`/rebotarm/disable`；
- `FollowJointTrajectory`、`trajectory_stop` 和 `safe_home`；
- 六轴与夹爪状态、反馈新鲜度和错误处理；
- 夹爪位置/抓取服务及有界保持；
- 底层关节限位、格式和通信失败拒绝。

### 曲线与准备契约

- 六轴严格按 `joint1..joint6` 重排全部位置及导数字段; 时间严格递增。
  只有 q 使用线性参考(C0), q/v 使用三次 Hermite(C1), q/v/a 使用五次 Hermite(C2)。
  同一轨迹混合缺失 v/a 或只有 a 没有 v 时拒绝, 不静默降级或给所有中间点补零。
  低阶兼容只检查各段有限导数, 不能把节点处的导数跳变当作满足加速度/jerk 约束。
- `PreparationContext` 明确携带设备会话、目标代次、最后成功发送的保持目标、反馈及其
  观测时间、静止/使能/忙状态。静止证据由调用者提供, 不能由单帧位置推定。
  起点修正前必须使能、静止、空闲且反馈新鲜; 反馈年龄上限 150 ms, 未来容差 5 ms。
  按用户追加要求，取消反馈及原 t0 位置到保持目标的绝对误差门限；
  准确规范化曲线仍须通过完整限值和碰撞检查，原始首点越限不能被起点替换掩盖。
- 校验前将 t0 对齐保持目标, 将已提供的首尾 v/a 归零; 原中间点、时间及最终位置
  保留。延迟的单目标显式补入 t0 保持起点; 零时长位置变化拒绝。此后生成、检查和采样
  使用同一份系数, 控制器正式接入时不得再次修改起点或重新拟合。
- `point_to_point` 给出静止到静止的完整五次约束, 默认 0.4 s; 最低时长提示仅用于报告,
  不自动延时。0.02 rad / 0.2 s 的 jerk 峰值为 150 rad/s³, 超过配置 20;
  同幅度最低时长约 0.391487 s, 0.4 s 时为 18.75 rad/s³。
  **生产键盘仍为 0.02 rad / 0.2 s**, 本批没有更改。
- 读取规范 URDF 位置限位与 `joint_limits.yaml` 的六轴 v/a/jerk 上限。对各段解析导数的
  实根及端点检查位置过冲和动态极值; 缺限值、数值求解失败或非有限结果为 unknown。
  浮点求根不是形式化区间证明, 极端病态输入仍是后续数值审查边界。
- 碰撞沿实际重建曲线采样, 用段内最大速度约束关节空间步长不大于 0.02 rad,
  加入内部位置极值, 不按端点距离遗漏往返, 不稀释样本。注入的检查器必须使用完整夹爪状态,
  检查数/请求数必须等于生成样本数; 碰撞拒绝, 未知/异常/缺检查器不得生成候选。
  这是离散覆盖, **不是连续碰撞证明**。
- `PreparedTrajectory` 是冻结的离线候选, JSON 携带版本、原约束、同一组系数和上下文。
  当前 Python 往返要求系数与版本生成规则精确一致; 尚不构成未来跨语言 ABI。
  接收方须在新鲜上下文中复核会话/代次/保持目标, 变化即作废。
  它不是硬件执行许可, 也没有实现真实 ROS 校验服务、场景快照锁定或原子接纳事务。

### 离线分析入口

在仓库根目录执行, 输入为 `joint_names` 与 `points` 的 JSON; 每个点含秒制
`time_from_start`、六轴 `positions` 及可选的完整 `velocities`、`accelerations`。
可选 `context` 对应上述 `PreparationContext`, `--now` 与 `observed_at` 使用同一离线时间源。

```bash
python3 scripts/analyze_p005_trajectory.py \
  tests/fixtures/p005_moveit_trajectory.json \
  --output /tmp/p005_moveit_report.json
```

报告包含规范化曲线、极值、连续性等级、原始点间隔及相对旧逐点保持/线性路径的偏差。
工具不创建 ROS 节点或访问设备, 不连接碰撞服务; 数值通过也只能得到 unknown,
不能拿报告发运动。超限/非法输入退出 2; 输出只允许新文件, 不覆盖旧证据。
上述真实样本会因重建曲线 jerk 超限退出 2。

## 反馈状态来源与恢复

六轴与夹爪共用控制器已验证缓存的读取和可用性判定。采集路径依据每个电机独立的
接收序号登记样本、观测时间和错误；状态查询不访问总线、不更新时间、不写入错误。
已删除重复的 `_gripper_status_code`，夹爪控制算法仍保留位置、速度和力矩缓存。

| 反馈情况 | 对外状态码 | `ArmStatus.error_codes` 原因分类 |
| --- | --- | --- |
| 尚无可信首帧 | `255` | `WAITING_FIRST_FRAME` |
| 读取失败或请求窗口内接收序号不推进 | `255` | `READ_FAILED`，附控制器、电机或序号信息 |
| 超过反馈有效期 | `255` | `STALE`，附数据年龄和超时阈值 |
| 位置、速度或力矩含非有限数值 | `255` | `INVALID_VALUES` |
| 坐标超出对应关节/夹爪范围 | `255` | `INVALID_COORDINATE`，附名称、原始角度和边界 |
| 夹爪显式置零验证失败或未完成 | `255` | `ZERO_INVALID`，附验证详情 |
| 新鲜合法的失能、使能或电机故障反馈 | 原码 `0`、`1`、`11` 等 | 不转换为反馈采集错误；保留电机故障含义 |

原因继续通过已有 `ARM_FEEDBACK` / `GRIPPER_FEEDBACK` 错误项及日志传递，Dashboard
沿用现有错误栏。六轴仍按整臂健康状态汇总，任一轴采集错误会使六轴状态统一不可用；
夹爪按自身反馈判断。共享总线事务失败可能同时影响七个电机，不代表保护范围合并。

新反馈越限时，不得因上一条合法样本仍在缓存中而恢复健康；采集错误优先于旧样本。
合法新帧到达后清除该电机的当前采集错误，状态立即恢复为新样本的原始状态码，
结果与状态查询次数无关。夹爪有限但越限的原始坐标保留供诊断和显式置零使用，
仍报告不可用并拒绝动作。`ZERO_INVALID` 必须经下一次显式置零验证成功才清除；
已有命令失败和保护性失能记录也不会被普通新帧抹除，恢复反馈不会自动使能或续发命令。

ROS 发布使用原子快照：数值、状态码、接收序号和反馈观测时间成套读取，夹爪开口
直接由同一快照换算。六轴批次取最旧反馈时间；夹爪保留独立反馈时间，六轴读取失败时
仍发布夹爪状态。首次发布按样本年龄换算 ROS 时间，同一缓存重发沿用旧时间戳；
夹爪首帧前使用零时间戳，不可用时米制开口为 NaN。`ArmStatus` 是当前健康快照，
状态码和原因一起读取，其消息时间仍为发布时刻。新鲜合法的电机故障码可发布，
动作和使能入口的健康要求仍保留。

### ROS 订阅延迟的离线隔离

验收端报告源数据超过 150 ms，并不能单独区分底层缓存过期、发布停顿与订阅调度
停顿。判断时必须对齐进程内缓存观测时间、发布时刻、消息源时间、DDS 接收时间、
回调入口和独立监测时间。同一台机器的 DDS 时间戳与源消息时间使用墙钟；回调间隔
使用单调时钟，并检查墙钟与单调时钟的偏差是否跳变。

2026-10-28 的无硬件对照在本机 rclpy `7.1.12` / `rmw_fastrtps_cpp 8.4.4` 环境
复现了多线程接收空档。仅记录已送达消息的年龄会漏掉这一现象：恢复后收到的新帧
可能很新鲜，但独立监测已在空档中观察到旧帧超过门限。默认订阅 QoS 事件等待参与
这一复现；去掉事件监听或改用单线程接收的对照结果见[项目状态](../../reference/project_status.md)。
这不是放宽门限、更新时间戳或删除生产事件诊断的依据，也不能证明此前所有真机
过期具有同一原因。

仓库提供只使用内存假缓存与生产发布器的对照工具。加载 Jazzy 和工作区 overlay，
选择空闲非零域后运行：

```bash
python3 scripts/diagnose_feedback_latency.py --domain-id 174 \
  --output-dir log/feedback_latency_comparison --duration 20 --with-pose
```

工具检查域中已有节点、使用专有命名空间，禁止导入 MotorBridge/串口，分别运行
多线程与单线程订阅。它不构造硬件控制器、不发运动请求。采样先存内存、结束后写盘，
输出发布端、订阅端 JSONL 和 `comparison.json`。`--without-qos-events` 仅供对照
默认事件监听对等待集的影响；不修改生产节点。运行目录必须不存在，避免覆盖证据。
源数据门限保持 150 ms，发布端比订阅端延后退出，启动发现和结束断流不计入观测窗口。

后续真机验收应让专用单线程接收器持续处理反馈，把规划、碰撞查询和日志写盘放在
接收路径之外，并同时保留控制器缓存审计。位姿兼容服务与 Action 含同步等待，不能
直接把整个生产节点改成单线程；生产多线程等待路径的长期处理需另行验证。

## 控制器拆分的行为基线与设备边界

拆分以 `102c218` 的公共 ROS 名称、消息类型、显式使能、反馈序号/年龄、
夹爪 0～90 mm 和六轴规范限位为基线。Python SDK 固定提交为
`6a49302804f25e624995e771acb6d61896d1856d`；原目录仅保留作来源和纯计算对照。
本地 `configuration.py` 解析本包安装的 `arm.yaml/gripper.yaml`，channel 覆盖在内存完成；
只允许 damiao，验证六轴顺序、共享通道、ID 唯一性及有限参数。反馈契约是复制后的
不可变数值，MotorBridge 状态对象后续改变不会修改已验证样本。重连清除旧连接的
序号、请求和反馈缓存，并取消旧夹爪任务；必须重新收到可信首帧及显式使能。

`sdk_driver.py` 直接接 MotorBridge；`connect()` 才打开唯一 Controller，
一起注册六轴与夹爪七个句柄，关闭时逐个释放 Motor，再释放 Controller。
`controller_runtime.py` 使用持续运行的唯一设备线程。停控制循环只移除周期回调，
失能后仍采集反馈；验证失能并释放句柄后才退出线程，以有界 join 确认关闭。
禁止 self-join 和第二写入者；不使用 `Thread._stop()`。低层 disable 本身不 join。
目标、速度覆盖及轨迹游标由 `arm_execution.py` 持有，位置输出由
`arm_position_control.py` 生成。没有 SDK 控制循环或额外送点线程。
生命周期与透传等门面入口复制输入后进入 `device_requests.py` 队列，由运行时
串行执行。生命周期锁保护读者与交接；驱动的命令操作锁串行化模式切换、
六轴命令批次及设备启停/释放，夹爪及保护性失能直接使用总线锁。模式切换的寄存器稳定、
逐电机稳定及最终稳定等待均不占总线锁，反馈可在等待期间继续请求和读取；
同一电机的四项 POS_VEL 增益写入仍是一个总线事务，单次模式握手也保持互斥。
原有稳定延时、严格失败回执及 150 ms 反馈过期门限不变，不通过重置旧样本时间
掩盖过期。反馈路径只取总线锁；需同时取锁的驱动操作按命令锁 → 总线锁排序。
较长握手的稳定等待由同一设备线程继续采集真实新帧，不运行运动周期；已进入的
单次 ABI 调用仍受底层超时限制，停止请求不能打断它，不能将此描述为硬实时急停。
反馈采集归 `feedback_acquisition.py`，只读快照归 `feedback_reader.py`；
六轴、夹爪、重力的事务分别归 `arm_controller.py`、`gripper_controller.py`、
`gravity_controller.py`，状态与计算仍归各自执行/算法组件。生命周期事务及状态归
`lifecycle.py`；manager 只装配和公开转发。

### 请求、资源与停止确认

- 普通请求容量 64，停止/失能保留 4 个位置；按优先级、提交顺序执行，每轮最多处理
  4 个请求后让出周期。普通请求默认 2 s 有效，生命周期按操作为 5～10 s，透传为 0.25 s。
- 有效期约束开始执行的时刻；超时仅能撤销尚未开始的请求，已开始事务继续等待真实结果。
  设备会话和六轴/夹爪分别有代次，停止、模式和会话交接使旧排队请求失效。
- 六轴与夹爪可并行，分别管理任务；透传的 reject/preempt 在设备线程内原子处理。
  接替六轴轨迹或重力补偿前先确认保持；夹爪先确认中性命令成功发送。旧任务取消
  携带身份/代次，不能停止后续目标。透传断流 0.25 s 后六轴转当前位置保持、夹爪转 MIT 中性。
  租约到期触发交接，实际完成还受设备事务和模式确认时延约束，不保证 0.25 s 内物理停稳。
- 透传拒绝非有限数值、超出配置的位置/速度及协议 MIT 增益/力矩。六轴命令模式须匹配
  显式设备模式；夹爪模式在资源交接后确认切换。`command_guard.py` 统一返回准入决策，
  生产与假设备测试不再根据是否存在请求队列跳过校验。无效透传在取消旧任务或切模式之前
  拒绝；六轴接替会转 POS_VEL 保持，接替请求须匹配交接后的模式。透传仍不具备上层碰撞规划。
- FJT 接纳和起点检查归 `arm_controller.py` 与 `arm_trajectory.py`；周期线程推进并确认终点。保留
  起点 0.10 rad、终点 0.03 rad 和 2 s 沉降预算，成功反馈必须晚于末点发送。
  健康超差转实测保持，不自动失能。safe_home 使用独立任务、0.02 rad 到位容差及任务速度覆盖。
- FJT 取消须保持命令成功发送，且后续新帧连续 0.2 s 速度不超过 0.05 rad/s，
  确认预算 2 s；不检查位置极差或相对保持命令
  的绝对误差。失败报告停止未确认，不能伪称 canceled。
  ROS Action 只复制请求、读快照和映射终态，不推进执行时间轴。发布器始终只读缓存。
  `ArmStop` 按周期推进，首次保持发送成功后才开始反馈确认；重复缓存不累计静止时间。
  运行时保存原请求的周期结果，调用侧等待事件，设备线程继续服务周期与失能请求。
  确认期间拒绝接替运动；失能、模式或目标代次变化使原等待失败，透传续体不得发送。
  超时仍保持使能和当前保持目标。单次 ABI 写入及模式握手仍不可被软件优先级打断。

保护失能由 `CommandGuard` 按故障会话锁存：先停止周期输出，同一未确认故障只自动
下发一次共享控制器失能。持续反馈过期、发送失败或错误重入不再每周期重发或刷保护日志。
反馈采集继续，状态保留 `DISABLING`；仅反馈恢复不能恢复输出。失能发送失败仍记错误，
操作员须显式请求 `/rebotarm/disable` 重试；新鲜七路反馈确认失能后才解除锁存，随后仍须
显式使能。任务清理异常不跳过本次保护失能尝试。这是软件故障策略，尚未做实机故障注入验收。

驱动、目标准入、重力模型和反馈检查共用规范 `rebotarm.urdf` 的六轴位置范围，只在加载时
解析为只读数值，不在周期内读文件。缺失、重复、非有限或反向范围拒绝启动；显式加载的
其他动力学模型仍必须与规范范围一致。修改规范模型仍需评审和对应硬件验收。

### 位姿兼容接口与 SDK 退出

`legacy_backend.py`、SDK 路径注入和全部生产 SDK 导入已删除。只迁现用能力，原 SDK 树
保留作参考。motion 的 `pose_kinematics.py` 独立实现规范模型 FK、阻尼 IK、回溯和可注入
随机源的重试；`cartesian_trajectory.py` 以最小 jerk 在 SE(3) 上采样，逐点以上点解跟踪，
任一点不收敛拒绝整条路径。默认采样 20 ms，非正时长按平移距离估算且至少 1 s，
路径和重定时均限制在 120 s 内；重定时复用现有保路径实现及配置的速度/加速度/jerk 限位。

`pose_compat_node.py` 由唯一硬件 launch 组合，提供原位姿 Service/Action 名称。
服务使用 IK 两点路径，Action 使用笛卡尔采样；两者均要求新鲜关节和夹爪状态、显式使能，
检查全部重定时输出点并补齐段内不超过 0.02 rad 的碰撞采样。碰撞未知或非唯一 FJT 服务端
即拒绝。服务 success 只表示 FJT 已接纳；Action 等待 FJT status=SUCCEEDED / error_code=0。
进度按重定时后时长估算，不能代替到位确认。执行期间检查 0.20 rad 跟踪误差与配置动态限位，
重复源时间戳不重复差分。迟到接纳仍跟踪并取消；取消须 FJT 终态与新鲜静止反馈，未确认前
阻断本节点后续请求。该入口校验给定路径，不进行避障搜索。

固定对照样本为 `tests/fixtures/controller_pose_vectors.json`：在同一规范模型上，四组可达
目标（含上限及近奇异）新旧均收敛，最大关节差约 6.05e-11 rad、回代残差小于 1e-4；
不可达 (4,4,4) 两者均拒绝。1 s 笛卡尔样本均为 51 点，新末点残差约 5.46e-5，
端点关节差约 2.04e-6 rad。旧采样末点发送时刻为 0.980392 s，本地覆盖完整 1 s 后再重定时，
这是明确的时序修正；不据此宣称设备运动等价。

离线 ROS 验证入口为 `tests/fixtures/controller_batch6_ros_probe.py`：在空闲隔离域启动
真实 move_group、禁用其假关节源后运行该入口。入口强制装配内存假句柄并拦截 SDK 导入，
覆盖默认失能拒绝、FJT 执行和取消、MoveIt ExecuteTrajectory 经 simple_controller_manager
到唯一 FJT、IK 服务接纳和位姿 Action 到位。它不打开真实通道，不构成实机验收。

普通 POS_VEL/MIT 批次返回已发送、失败和未尝试电机回执；发送错误后停止剩余
普通写入、作废游标代次，去重请求共享 Controller 保护失能。模式寄存器失败报告
电机和寄存器地址，终止切换/使能且不缓存成功模式。失能尚未验证时保持
`DISABLING` 和未知输出状态，IDLE 发布或首周期竞态不能清掉故障门；再次运动
须先显式失能并验证，再重新使能。关闭失败也保留未知状态及错误，不假报已失能。
健康的目标校验/规划失败在写入前拒绝，保留当前位置保持。

节点收到退出信号时，若电机仍使能，停止运动并保持控制，继续响应服务，等待现场确认后
显式调用 `/rebotarm/disable`；再次请求退出才释放设备。可选的退出停靠失败时同样保持，
停靠成功也不自动视为本轮安全基线。确认失能后关闭会再次检查新鲜失能反馈再释放句柄，
状态不明时保留连接和错误。ROS 上下文若已在外部关闭，进程会保留硬件控制线程，但 ROS
服务无法继续使用，此时不能通过新开控制器或第二个串口连接尝试恢复。现场人员应先可靠
支撑机械臂及负载，按现场流程使用硬件急停或驱动断电停止输出；确认设备安全后再结束
保留的进程、核对串口释放，重新启动并获取新鲜默认失能反馈。普通退出拒绝时 ROS 仍可用，
应优先在确认基线后使用显式失能服务。强制终止无法由该软件流程拦截。

`controller_kinematics.py` 使用规范六轴约化模型提供纯数值 FK; ROS Pose 转换归发布和适配层。
此前相同输入的新旧模型对照得到四组位置差均为 0 m, 姿态差最大 2.29e-16 rad,
属于数值舍入。默认检查现使用固定样本, 不再依赖旧 URDF; 命令及边界见下节。
规范 `joint3` 命名和 J2/J3 `+0.02 rad` 限位保持不变。

## 重力补偿控制

补偿使用 `rebotarm_moveit_config/config/rebotarm.urdf` 的六轴约化模型，保持
`joint1..joint6` 顺序和原始反馈坐标；夹爪关节锁定在模型零位。模型加载检查
关节限位与硬件一致，力矩上限读取 URDF effort，且不得超过前三轴 27 N.m、
后三轴 7 N.m 的软件上限。重力与雅可比使用同一模型；末端速度采用
`LOCAL_WORLD_ALIGNED`，对应 end_link 原点速度和基座坐标轴。

补偿配置位于 `src/rebotarmcontroller/config/gravity_compensation.yaml`，随包安装，
可用控制器参数或唯一硬件 launch 的 `gravity_config` 显式覆盖。保留 Kp=7、
Kd=0.8；积分按实测 dt 计算，增益 1 N.m/(rad*s)，限幅 0.5 N.m。
总力矩估计包含电机端 PD 与前馈；同时限制前馈和总力矩，以及总力矩变化率
（前三轴 108 N.m/s、后三轴 28 N.m/s）。饱和时为前馈保留协议余量，必要时降低
PD 增益。这些是软件边界，实际反馈间隔中的电机输出仍需实机验证。

`gravity_xyz_m_s2` 是 base_link 中的重力向量，默认水平安装；
`payload_mass_kg`、`payload_com_xyz_m` 是额外负载的质量与 end_link 中的质心。
默认额外负载为零，不重复加入 URDF 已有的末端 0.5 kg。URDF 缺少独立手指的
惯性，当前 MuJoCo 另外具有手指、D405 相机和支架的估计质量；仿真与补偿交叉验证
必须显式对齐这些附加载荷。仿真网格推算出的手指质量不能当作实物称量结果。
实际安装的相机、支架、手指及抓取物负载需要测量后配置；零位和关节方向仍需
在实机逐轴核对，不能由模型加载或仿真证明。

控制频率使用 arm.yaml 的 rate（当前 100 Hz），回调耗时计入本周期预算，按下一截止时间
等待剩余时间；错过下一周期时重新排期，跳过积压周期。反馈刷新上限默认 50 Hz；
不把 SDK 的 500 Hz 默认值视作实测能力。补偿中每 5 s 输出 `gravity diagnostics`，
包括实际最大周期、回调耗时、错过截止时间次数、逐轴新序号观测速率、反馈年龄
及模型路径/摘要、重力方向和负载配置，也可通过 `gravity_compensation_diagnostics()` 读取。
观测速率统计每次接收到的最新样本，不把重复缓存读取或重复 ROS 发布计为新反馈。
Python 线程与 sleep 不提供硬实时保证；新诊断用于实机采样后决定可用控制带宽。

连续三周期出现回调耗时大于配置周期或周期间隔超过 1.5 倍，停止拖动跟随，
在最新验证位置维持有界 MIT 保持，并报告 `GRAVITY_HOLD`。
模型计算异常采用同一保持路径，不让异常退出唯一写入线程。
模式切换必须全部成功，并在切换后刷新反馈；进入失败时健康硬件恢复到当前位置
POS_VEL 保持。发送失败、反馈失效、电机异常或保持恢复失败时按严重故障保护性
失能。退出补偿重新获取新反馈并确认 POS_VEL 切换结果；不在停止失败时另起写入者。

`GRAVITY_HOLD` 锁存后，网页显示故障保持和具体原因，补偿活动及要求补偿的录制就绪状态
均为 false。反馈新鲜、机械臂仍使能且错误仅为 `GRAVITY_HOLD` 时，操作员可确认现场状态后
点击“退出重力补偿”，成功交接到当前位置 POS_VEL 保持后清除该故障，再显式启动补偿。
显式失能在六轴及夹爪的新反馈确认后同样清除重力故障。退出或失能确认失败时保留锁存；
其他控制器、电机和反馈错误继续沿用原有门禁，重力补偿保持原有超时与力矩门限。

新增软件边界和模式切换连续性尚未作为当前基线实机验收结果。当前任务只完善
已有重力补偿，笛卡尔阻抗控制器仍未实现。

## 验证结果

控制器接口、失能启动、反馈刷新、使能回滚、轨迹停止和状态发布由控制器测试与分层测试覆盖。具体命令见 [系统运行命令](../../reference/commands/system_runtime.md)。

## 边界与未完成

真机启动前必须确认串口唯一占用、fresh feedback、现场净空、支撑和急停。健康但可恢复的任务失败不得把机械臂直接失能在未知姿态；软件测试不替代物理安全验收。
