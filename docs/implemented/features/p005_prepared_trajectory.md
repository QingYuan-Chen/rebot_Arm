# P005 共享轨迹与 prepared_v1 执行

> 范围：共享六轴轨迹、网页组合与独立夹爪执行及软件/MuJoCo 验证；现场运动表现由用户验证。

## 修订协同接口

当前公共 `/rebotarm/follow_joint_trajectory` 只执行完整 `joint1..joint6`，单位 rad。
七轴、单手指及携带右指的旧 FJT 明确拒绝，不静默投影。六轴 q/qv/qva 的 C0/C1/C2
兼容及系数载荷 v1/v2 保留。URDF mimic、模型、惯量、限位和控制增益不变。

网页 prepared_v1 的关节、键盘和组合操作使用
`/rebotarm/execute_teleop_motion`（[ExecuteTeleopMotion](../../../src/rebotarm_msgs/action/ExecuteTeleopMotion.action)）：

- Goal：完整六轴 trajectory、move_gripper、gripper_position（双指总开口 m）、gripper_max_effort。
- Feedback：preparing/executing/stopping、机械臂进度、夹爪状态、实际开度及六轴参考/反馈。
- Result：整体终态、arm_state、gripper_state 和失败原因。提交或一侧完成不能作为整体成功。

后端准备通过后在同一设备周期登记六轴与独立夹爪目标。夹爪沿用原限速、到位、超时及
中性释放，力矩沿用独立接口默认值和配置上限，不参与 FJT 插值或机械臂重定时。
两侧分别到位并完成清理后整体成功，不保证同时到达；机械臂继续保持命令终点。
取消、停止、单侧失败、重连统一终止任务，未完成侧停止，停止确认前保留预约。
内部开合必须持有本次预约身份；普通独立请求忙时拒绝、不排队。健康可恢复失败保持使能。
总线仍逐电机发送并记录真实回执，不承诺硬件原子同步；迟到响应和旧收尾不能影响后继任务。

`/rebotarm/trajectory_capabilities` 是版本 2 的只读 JSON 快照，仅声明六轴 FJT、
网页 Action 版本 1 和 independent_position 夹爪，包含系数版本、
生效夹爪速度/力矩、模型限值摘要和启动/重连会话。规划消息绑定其 revision，缺失、过期、
重连或配置不一致拒绝；该快照不代表使能或运动许可。

规划阶段通过 `/rebotarm/retime_arm_trajectory` 缩放六轴轨迹的时间、速度和加速度，
保留节点位置与相对时序。自动模式返回最终时长，固定模式超限提示所需时长并拒绝。
按实际规划曲线计算极值，并在纳秒编码后重建复核；不再额外扰动首点检查量化包络，
实际起点规范化后的准确曲线仍由准备服务复查。位置越限和非法输入不能靠
缩放修复。服务总期限 2 s；准备服务及执行器不重定时，预算仍分别为
`min(2.0 s,0.2T+0.25 s)` 和 `1.2T+0.5 s`，T 为最终规划时长。

MoveIt 响应链为 TOTG → Ruckig → 执行曲线重定时 → ValidateSolution → DisplayMotionPath。
motion 采用混合构建，C++ 插件复用 Python 数值服务。MoveIt RobotTrajectory 不保存
JointTrajectory header，插件缓存最终完整数值并由原 simple controller manager 的装饰器
匹配后恢复能力绑定；缓存缺失要求重新规划。prepared 分支 TOTG `min_angle_change=1e-7`，
避免其默认 0.001 同时应用 rad/m 时吞掉亚毫米手指轨迹；legacy 保持原值。

内部准备明确绑定两种碰撞策略：网页 Action 固定使用 WEB_CLOSED（双指均为零）；
普通 FJT、MoveIt 机械臂、示教和视觉使用 FIXED_CURRENT（准备时取得的真实开度，全段固定）。
真实夹爪快照与计算用双指位置分别保存，响应绑定策略，后端原子复核后执行。
闭合替代值仅写本次计算副本，不修改反馈、界面实际开度、全局场景、附着物或碰撞规则。
页面显示“按闭合夹爪模型检查”，不代表实际张开手指范围已检查。
同一 MoveItPy 只读场景快照检查全机器人及附着物，包含全部六轴节点和内部位置极值，
机械臂相邻跨度≤0.02 rad。超预算、超时或覆盖不完整拒绝，不抽稀，不宣称连续碰撞证明。
执行中观察到相关场景变化时整体停止。周期延迟直接采当前六轴参考，不补发积压点。
机械臂末点仍须满足原 0.03 rad 到位容差，独立夹爪沿用电机角 0.12 rad 到位容差；
不恢复已删除的逐周期参考误差中止或约 0.001144 rad 位置偏差准入门限。

独立夹爪到位后，下一段运动使用新鲜实际开度，不使用请求目标。关节状态桥分开保存并发布
机械臂/夹爪源时间；新机械臂帧不能刷新旧手指，缺失或过期手指不补零、不冒充当前状态。
MoveIt 保留 `arm` FJT 和 `gripper` 独立 GripperCommand 两组，移除 `arm_with_gripper`。
`/rebotarm/gripper/moveit_command` 把左指 m ×2 交给原总开口接口，反馈/结果 ÷2；
单左指曲线仅用于规划限速预算，不是 FJT 执行能力。
示教按名称提取六轴、保留原始夹爪数据供查看，派生 `.prepared.v3.jsonl` 不覆盖原文件，
页面提示夹爪不参与回放。视觉先独立预张爪完成，再按实际开度规划预抓取和接近，止于接触前。

网页只编辑机械臂关键点，夹爪为单次目标，组合按钮交接一次性 `plan_id`。
网页遥操作仅提供组合执行和停止按钮，不再提供单独关节或夹爪执行入口；任务显示简短
状态，详细失败原因可查看状态提示，计划或提交被拒绝时会弹窗说明。其他独立接口保留。
预览不按 30 s 或位置微小变化失效；缓存仍有数量上限，能力变化仍须重新预览。
执行准备以当时预约的机械臂保持值规范化起点，再检查整条六轴曲线的限值和碰撞；
因此起点变化后实际准备的曲线可能与先前预览不同。
夹爪不再支持延迟、多关键点或第七轴插值预览。机械臂关键点使用六项 positions，
可明确给 velocities/accelerations；新节点默认声明静止约束。
编辑或重新进入预览会清除旧计划，从当前反馈初始化；实际执行仍须通过碰撞准备。
键盘继续 `0.02 rad /0.4 s` 独立单步、不排队。

`/diagnostics` 发布只读准入快照，区分失能、模式、资源、新鲜度、保持命令是否已确认、夹爪及
场景条件；日志保留数值、门限和代次。网页区分提交、接纳、成功与再次可执行，快照超过1 s
显示未知。标准 FJT 直接 REJECT 无原因字段，当前快照不能冒充该次拒绝原因。
按用户追加要求，取消六轴实际位置到保持命令的约 `0.001144 rad` 误差准入门限。
机械臂新任务准入不再要求速度门限、连续静止窗口或该窗口所属的保持代次；不修改设备保持目标。
反馈新鲜度、资源、执行代次、夹爪健康及场景检查保留，不自动 Stop/Safe Home 解锁。
取消及停止事务仍需其独立的静止确认；夹爪准备仍要求空闲、新鲜及静止反馈。

## 组件与契约

`rebotarm_trajectory` 提供不可变数据、结构校验、系数解码和时间采样。
`rebotarm_motion` 生成系数、规范化边界，检查段内位置、速度、加速度、jerk 与碰撞。
控制器拥有设备线程、发送确认、任务及资源；MuJoCo 拥有物理时间、控制模式和生命周期。
控制器、仿真都不导入 motion 实现，不把固件速度上限当作参考曲线的有符号速度。

| 输入 | 插值 | 连续性 |
| --- | --- | --- |
| q | 线性 | C0 |
| q/v | 三次 Hermite | C1 |
| q/v/a | 五次 Hermite | C2，jerk 不保证连续 |

同一轨迹混合缺失导数拒绝。C0/C1 段内导数检查不代表节点跳变满足高阶限值。
网页点对点和键盘由 motion 构造首末完整 q/v/a 约束；prepared 键盘默认为
`0.02 rad / 0.4 s`，独立起停、忙时拒绝、不排队。legacy 时长仍为 0.2 s。
PoseCompat 保留 q-only；示教保留完整可用字段和非零中间导数，混合字段拒绝。
MoveIt 对齐段和录制段的导数等级不同时明确拒绝，不能删除规划导数来迁就录制字段。

`/<ns>/follow_joint_trajectory` 始终由选定的唯一后端提供。
`/<ns>/prepare_arm_trajectory` 是内部服务，契约位于
[PrepareArmTrajectory.srv](../../../src/rebotarm_msgs/srv/PrepareArmTrajectory.srv)。
后端从 Goal 接收开始预留六轴和夹爪，准备期间继续保持；期限为
`min(2.0 s, 0.2T + 0.25 s)`，使用同机单调时钟。MoveIt 预算仍为 `1.2T + 0.5 s`。
准备失败、超时、超限、碰撞均拒绝，不拉长时间、裁剪或降低连续性。

反馈新鲜时，六轴起点规范化到最后成功发送的保持目标，不再按 `POSITION_SPAN` 限制
反馈残差或六轴首点修正幅度。越界原始首点仍拒绝，规范化后的整条曲线须通过完整限值与
碰撞检查；超限仍拒绝，不在准备时改时间。
首末已有导数归零，中间导数、原时间及末点位置不变。返回的精确系数绑定会话、
执行代次、保持目标、真实夹爪起始状态/代次、碰撞策略、能力及场景版本。
所有执行曲线均为六轴，手指按本次策略全段固定。实际接纳再次原子复核；
取消、停止、失能、重连和已观察到的绑定变化使结果失效，迟到结果不能发送。
普通夹爪运动在准备、执行和停止确认期间拒绝，保护性释放保留可达并撤销绑定。

碰撞检查复制完整 RobotState（包括附着物），填入六轴及本次固定双指，在同一
MoveItPy `read_only()` 场景锁中完成所有样本。按段内速度极值安排 ≤0.02 rad 的机械臂跨度，
包括内部位置极值；超预算拒绝，不抽稀。场景摘要包含环境、附着物、碰撞规则和固定变换，
排除反馈关节与时间戳。执行中已观察到相关环境变化即停止保持，不承担动态避障。

实机周期按单调时间、MuJoCo 每个物理步按仿真时间直接采样，不补发过期点。
只有完整发送成功才推进确认；正常完成保留最终命令目标，成功仍要求末点发送后的新反馈。
物理收敛观察与 Action 成功判定独立，不修改既有容差。

### MoveIt/MoveItPy 退出段错误修复

第三批交付后单独定位并修复工程启动链中的退出问题。本机依赖为 Jazzy
MoveIt 2.12.4、rclcpp 28.1.22。GDB 在没有机械臂后端的 MoveIt 演示中复现：
轨迹执行管理器析构时，`libmoveit_simple_controller_manager` 先被 `dlclose` 卸载，
随后 `rclcpp::CallbackGroup` 释放 action 客户端的弱引用控制块。其虚表地址
`0x7fffe82a7d88` 落在此前插件的只读映射 `0x7fffe82a7000–0x7fffe82aa000` 中，
卸载后访问该地址即触发 SIGSEGV。MoveItPy 复用相同轨迹执行管理器，因此同样受影响；
单独调用 `robot.shutdown()` 不能修复这个库与对象的生命周期顺序。
上游相同症状参见 [moveit2#1597](https://github.com/moveit/moveit2/issues/1597) 和
[moveit2#3721](https://github.com/moveit/moveit2/issues/3721)，本结论以本机调试证据为准。

工程修复位于唯一共用的 `moveit_demo.launch.py`：只给 move_group 与准备节点设置
进程级 `LD_PRELOAD`，通过 ament 索引定位控制器插件，使其映射覆盖所有相关对象的
析构期。保留用户已有预加载项，插件缺失在启动前失败；其余节点的环境不变。
`rebotarm_bringup` 显式声明插件运行依赖。未修改系统二进制、运动行为或安全门限，
未通过跳过析构、屏蔽信号、忽略段错误或改写退出码规避问题。
这是针对当前配套依赖的生命周期兼容措施；上游修复并完成同样退出回归后可删除。
