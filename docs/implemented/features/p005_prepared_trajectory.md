# P005 共享轨迹与 prepared_v1 执行

> 范围：共享轨迹、协同位置执行及软件/MuJoCo 验证；现场运动表现由用户验证。

## 修订协同接口

`prepared_v1` 的网页组合操作使用一条联合计划、一次 FJT 接纳和一个整体结果。
内部顺序为 `joint1..joint6,left_finger_joint`，前六项单位 rad，左指单位 m；网页继续
显示双指总开口，右指位置、速度和加速度均为左指相反数。URDF 补充 mimic 关系，未改
几何、惯量、限位、控制增益和 MuJoCo 原有耦合。

唯一公共 `/rebotarm/follow_joint_trajectory` 支持六轴、七轴和单左指请求。单夹爪请求
冻结六轴保持目标；额外提供右指时校验全部镜像字段，任意缺失机械臂关节均拒绝。
六轴系数载荷 v1 保留，具名扩展载荷 v2 显式记录维度、关节顺序。FJT `effort` 不代表
电机力矩上限，协同路径拒绝它；实际夹爪位置力矩上限来自启动配置，整体结束后中性释放，
不进入抓取保持。独立夹爪及 legacy 接口能力保留，活动协同任务期间普通请求忙时拒绝。

`/rebotarm/trajectory_capabilities` 是版本化只读 JSON 快照，包含关节集合、系数版本、
生效夹爪速度/力矩、模型限值摘要和启动/重连会话。规划消息绑定其 revision，缺失、过期、
重连或配置不一致拒绝；该快照不代表使能或运动许可。

规划阶段通过 `/rebotarm/retime_arm_trajectory` 统一缩放全部轨道的时间、速度和加速度，
保留节点位置与相对时序。自动模式返回最终时长，固定模式超限提示所需时长并拒绝。
按实际规划曲线计算极值，并在纳秒编码后重建复核；不再额外扰动首点检查量化包络，
实际起点规范化后的准确曲线仍由准备服务复查。位置越限和非法输入不能靠
缩放修复。服务总期限 2 s；准备服务及执行器不重定时，预算仍分别为
`min(2.0 s,0.2T+0.25 s)` 和 `1.2T+0.5 s`，T 为最终规划时长。

MoveIt 响应链为 TOTG → Ruckig → 执行曲线重定时 → ValidateSolution → DisplayMotionPath。
motion 采用混合构建，C++ 插件复用 Python 数值服务。MoveIt RobotTrajectory 不保存
JointTrajectory header，插件缓存最终完整数值并由原 simple controller manager 的装饰器
匹配后恢复能力绑定；缓存缺失要求重新规划。prepared 分支 TOTG `min_angle_change=1e-7`，
避免其默认 0.001 同时应用 rad/m 时吞掉亚毫米手指轨迹；legacy 保持原值。

同一只读场景快照逐时刻检查完整机械臂、变化的双指及附着物。采样包含全部节点和位置极值；
机械臂跨度≤0.02 rad，左指跨度≤0.00018 m（双指开口≤0.00036 m）。超预算、超时或覆盖
不完整拒绝，不抽稀，不宣称连续碰撞证明。执行中观察到相关场景变化时整体停止。

正式控制器的协同所有者持有统一时间轴与资源，六轴和夹爪仍分别计算、发送和确认。
每周期一次取参考时间，延迟后直接取当前样本，不补发积压点。部分发送保留真实回执，
不能提前成功或重发整批。最终命令发送、两侧新反馈到位和夹爪中性清理完成后才报告成功；
机械臂保持命令终点；与六轴单独执行一致，机械臂不再逐周期按 0.03 rad 跟踪误差中止，
末点仍须在发送后的新反馈中满足 0.03 rad 到位容差。夹爪同样不再逐周期按参考误差中止，
末点仍须满足电机角 0.12 rad 到位容差。执行期间仅因参考误差增大不会自动停止，
实际运动表现仍需现场观察。
取消、停止、失能、重连和保护释放撤销协同代次，停止确认前保留两类资源。

网页在现有页面编辑机械臂/夹爪关键点并预览，组合按钮只交接一次性 `plan_id`。
预览不按 30 s 或位置微小变化失效；缓存仍有数量上限，能力变化仍须重新预览。
执行准备以当时预约的机械臂保持值和夹爪位置规范化起点，再检查整条曲线的限值和碰撞；
因此起点变化后实际准备的曲线可能与先前预览不同。
夹爪关键点示例：`[{"time":0.3,"width":0.04},{"time":0.9,"width":0.05}]`，
time 为秒、width 为总开口米；末点早于全轨终点会保持。机械臂关键点使用六项 positions，
可明确给 velocities/accelerations；新增节点默认声明静止约束，合并另一轨道节点时保留
原导数。编辑或重新进入预览会清除旧计划，从当前反馈初始化；实际执行仍须通过碰撞准备。
键盘继续 `0.02 rad /0.4 s` 独立单步、不排队。

`/diagnostics` 发布只读准入快照，区分失能、模式、资源、新鲜度、静止、保持命令是否已确认、夹爪及
场景条件；日志保留数值、门限和代次。网页区分提交、接纳、成功与再次可执行，快照超过1 s
显示未知。标准 FJT 直接 REJECT 无原因字段，当前快照不能冒充该次拒绝原因。
按用户追加要求，取消六轴实际位置到保持命令的约 `0.001144 rad` 误差准入门限。
空闲静止窗口按实际反馈的速度建立，不修改设备保持目标；
反馈新鲜度、速度、完整窗口、资源、代次、夹爪健康及场景检查保留，不自动 Stop/Safe Home 解锁。

### 资源占用提示排查（2026-11-03）

用户反馈组合操作失败或取消后，网页显示 `arm/gripper resources reserved or stopping`，
第二次关节执行也存在。该消息合并了预约未释放与停止仍在处理两类状态，不能由它判断
最初那次 Action 的失败原因。最新真机日志中 20:47:16 准备成功，20:47:26 与 20:47:35
明确以 `arm resource busy` 拒绝新 Goal；当前可见日志缺少该次原始 Action 结果及停止证据明细。
实际默认安装区的相关控制器模块与当前源码一致。

当次仅排查，正式控制器＋内存假设备复现以下问题；后续修复见下一节：

- **失败/取消后的停止确认仍检查固定目标偏差。** `ArmStop.begin()` 以本次保持目标建立
  `StationaryEvidence` 固定锚点；约 0.001144 rad 的锚点位移检查仍在停止流程生效。
  加入固定 0.003 rad 残差，取消六轴/七轴任务后均得到
  `fresh stationary hold feedback not confirmed`。实际反馈窗口已静止，但锚点原因是
  `anchor_displacement`，停止超时后预约继续保留，新请求再次拒绝。
  保留未确认资源是安全约束，不能通过直接清空预约掩盖停止未确认。
- **七轴停止失败后可能重新进入固定夹爪检查。** 协同夹爪已经改变执行代次，
  `check_prepared_context()` 在停止超时后仍拿准备前固定夹爪令牌核验，假设备观察到
  自动重新发起停止，状态再次成为 `stopping`。这与第一次运动失败原因是不同问题。
- **六轴/七轴切换存在旧任务终态覆盖。** `update_task()` 对已结束的协同任务未核对
  当前执行代次。七轴取消完成后再执行六轴，旧 canceled 任务把新轨迹提前置为 IDLE，
  新轨迹成功后预约不释放；此时停止已经 confirmed，下一次仍报 busy。
  若旧七轴为 succeeded，新六轴执行中会提前清空预约，破坏夹爪排他。对照中纯六轴和
  七轴取消后再接七轴正常。该选择逻辑在取消残差准入门限前已存在。

证据位于 `log/p005_resource_admission_20261103/` 的 `fake_probe.log` 与
`stop_residual_probe.log`。前者记录任务代次、运行状态与预约，后者记录停止超时、
固定锚点残差及静止证据。它们只使用已有测试夹具和进程内假驱动，未增加测试文件、
访问串口、使能或驱动实机。现场最初失败的触发条件仍待原始 Action 错误进一步确认；
不把上述软件复现直接认定为现场唯一根因。后续应分别修正停止证据/预约生命周期、
协同停止后的上下文判定、任务代次归属，并拆开诊断中的预约与停止状态。

任务收尾只允许当前执行代次的协同终态影响生命周期，旧 succeeded/canceled/aborted
均不能提前清除或永久保留新任务预约。停止事务单独维护“仍在等待两侧”的续体状态，
机械臂先 confirmed、夹爪尚未静止期间仍拒绝新运动并加入同一停止；机械臂若再运动或
反馈异常，不能沿用旧确认。停止处理和失败保留预约期间不再复用准备前固定夹爪几何
触发重复停止。只有两侧都确认后才清理预约；超时仍保留资源，健康硬件保持使能。
迟到轮询/清理只处理原事务，不能改写后继准备或任务。

正式 ROS 假设备回归另复现并修复取消回调竞态：原回调等待完整停止，执行回调可能
在 ROS 进入 CANCELING 前先把 canceled 任务映射为 abort，表现为失败但内容是
`stop/hold confirmed`。现在取消回调在设备线程撤销执行许可、启动停止并交回周期续体
后即回接纳；FJT 任务终态仍等待停止证据，既不提前报告取消完成，也不允许迟到曲线发送。

## 组件与契约

`rebotarm_trajectory` 提供不可变数据、结构校验、系数解码和时间采样。
`rebotarm_motion` 生成系数、规范化边界，检查段内位置、速度、加速度、jerk 与碰撞。
控制器拥有设备线程、发送确认、任务及资源；MuJoCo 拥有物理时间、控制模式和生命周期。
控制器、仿真都不导入 motion 实现，不把固件速度上限当作参考曲线的有符号速度。

| 输入 | 插值 | 连续性 |
| --- | --- | --- |
| q | 线性 | C0 |
| q/v | 三次 Hermite | C1 |
| q/v/a | 五次 Hermite | C2，jerk 不保证连续 |

同一轨迹混合缺失导数拒绝。C0/C1 段内导数检查不代表节点跳变满足高阶限值。
网页点对点和键盘由 motion 构造首末完整 q/v/a 约束；prepared 键盘默认为
`0.02 rad / 0.4 s`，独立起停、忙时拒绝、不排队。legacy 时长仍为 0.2 s。
PoseCompat 保留 q-only；示教保留完整可用字段和非零中间导数，混合字段拒绝。
MoveIt 对齐段和录制段的导数等级不同时明确拒绝，不能删除规划导数来迁就录制字段。

`/<ns>/follow_joint_trajectory` 始终由选定的唯一后端提供。
`/<ns>/prepare_arm_trajectory` 是内部服务，契约位于
[PrepareArmTrajectory.srv](../../../src/rebotarm_msgs/srv/PrepareArmTrajectory.srv)。
后端从 Goal 接收开始预留六轴和夹爪，准备期间继续保持；期限为
`min(2.0 s, 0.2T + 0.25 s)`，使用同机单调时钟。MoveIt 预算仍为 `1.2T + 0.5 s`。
准备失败、超时、超限、碰撞均拒绝，不拉长时间、裁剪或降低连续性。

新鲜静止时，六轴起点规范化到最后成功发送的保持目标，不再按 `POSITION_SPAN` 限制
反馈残差或六轴首点修正幅度。越界原始首点仍拒绝，规范化后的整条曲线须通过完整限值与
碰撞检查；超限仍拒绝，不在准备时改时间。
首末已有导数归零，中间导数、原时间及末点位置不变。返回的精确系数绑定会话、
执行代次、保持目标、夹爪起始状态/代次、能力及场景版本。六轴请求冻结夹爪；七轴请求
按同一曲线移动双指。实际接纳再次原子复核；
取消、停止、失能、重连和已观察到的绑定变化使结果失效，迟到结果不能发送。
普通夹爪运动在准备、执行和停止确认期间拒绝，保护性释放保留可达并撤销绑定。

碰撞检查复制完整 RobotState（包括附着物），填入六轴及该时刻的镜像双指，在同一
MoveItPy `read_only()` 场景锁中完成所有样本。按段内速度极值安排 ≤0.02 rad 的机械臂跨度，
左指另按 ≤0.00018 m 采样，
包括内部位置极值；超预算拒绝，不抽稀。场景摘要包含环境、附着物、碰撞规则和固定变换，
排除反馈关节与时间戳。执行中已观察到相关环境变化即停止保持，不承担动态避障。

实机周期按单调时间、MuJoCo 每个物理步按仿真时间直接采样，不补发过期点。
只有完整发送成功才推进确认；正常完成保留最终命令目标，成功仍要求末点发送后的新反馈。
物理收敛观察与 Action 成功判定独立，不修改既有容差。

不匹配或能力未知拒绝，无失败后回退。真实硬件默认 legacy，专用 safe_home 等路径保留原语义。
日常 `mujoco_moveit_sim.launch.py` 已默认 prepared_v1，终端键盘须显式选择相同模式。
轻量 RViz preview 发布 legacy 能力，保留旧入口兼容，不提供 prepared_v1。

第三批将 `trajectory_execution_mode` 显式贯通 MoveIt、网页工作台、键盘遥操作和视觉抓取
的现有启动链。真机 prepared_v1 组合复用 `moveit_demo` 提供场景和准备服务，
唯一控制器及真实反馈仍由硬件片段拥有；键盘新分支不重复启动控制器、状态发布或 RViz。
轻量预演保持 legacy，四类真机日常入口首次交付也保留 legacy 默认；用户明确确认实测通过后
才另行切换其默认。独立底层启动始终保留 legacy 默认和显式选择，不自行补齐准备服务。

prepared_v1 为 0.02 rad / 0.4 s，legacy 仍为 0.02 rad / 0.2 s。

不再发布模拟落点污染物理反馈。`use_dashboard` 默认 false，不改变既有界面启动偏好。
终端键盘可另启动 `TeleopKeyboardNode --ros-args -p trajectory_execution_mode:=prepared_v1`。

### MoveIt/MoveItPy 退出段错误修复

第三批交付后单独定位并修复工程启动链中的退出问题。本机依赖为 Jazzy
MoveIt 2.12.4、rclcpp 28.1.22。GDB 在没有机械臂后端的 MoveIt 演示中复现：
轨迹执行管理器析构时，`libmoveit_simple_controller_manager` 先被 `dlclose` 卸载，
随后 `rclcpp::CallbackGroup` 释放 action 客户端的弱引用控制块。其虚表地址
`0x7fffe82a7d88` 落在此前插件的只读映射 `0x7fffe82a7000–0x7fffe82aa000` 中，
卸载后访问该地址即触发 SIGSEGV。MoveItPy 复用相同轨迹执行管理器，因此同样受影响；
单独调用 `robot.shutdown()` 不能修复这个库与对象的生命周期顺序。

[moveit2#3721](https://github.com/moveit/moveit2/issues/3721)，本结论以本机调试证据为准。
